# PLAN.md — переход на чистый Claude Code (финальная версия, 2026-07-04)

Контекст: отказ от Junie CLI (частые сбои) и AI Assistant-чата (неудобный UX)
в пользу Claude Code как единственного инструмента. Ранее — dual review
Junie(генератор) + Claude Code(аудитор); теперь оба процесса — Claude Code,
разные сессии/модели.

## 1. Разделение generate/audit — решено

- Генерация — любая модель (DeepSeek/Ollama для черновой механики допустимы),
  через switcher-обёртку из ~/.zshrc.
- Аудит — всегда Anthropic. Механизм: чистый терминал без switcher-обёртки
  + explicit `--model` flag. НЕ «флаг вместо env» — гарантию даёт чистое
  окружение терминала, флаг лишь выбирает модель внутри Anthropic.
- Enforcement на случай протёкшего env уже стоит: warn-non-anthropic.sh
  (SessionStart) + endpoint-gate в скилле audit-diff.
- Само-аудит — два сценария, не путать:
  - Сценарий А (продолжил аудит в том же чате, где генерировал) — закрыт
    инструкцией в начале скилла audit-diff: модель проверяет собственный
    контекст сессии и отказывается аудировать свой же дифф.
  - Сценарий Б (новый терминал, забыл флаг модели — аудит той же моделью,
    что генерировала) — ПРИНЯТЫЙ РИСК. Защита процедурная, не техническая:
    гейта для этого сценария нет (свежая сессия не имеет памяти о том, кто
    писал код). Промптом не закрывать.

## 3. Snyk — закрыто, на трёх уровнях (не смешивать)

- IDE-плагин (Cursor, PyCharm) — уже есть, работает независимо от CLI-агента,
  решения не требует.
- CI: pip-audit — НЕ добавлять. Решение пользователя без задокументированного
  сравнения; pip-audit не нужен.
- MCP-доступ для агента — НЕ добавлять по умолчанию. У агента есть bash,
  разовый `snyk test` через bash покрывает большинство случаев без постоянной
  интеграции. MCP — только если на практике интерактивный доступ к находкам
  в диалоге понадобится чаще, чем разовая проверка; по факту использования,
  не заранее.
